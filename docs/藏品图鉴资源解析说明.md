# 藏品图鉴 CSV 更新说明

本文记录从微信小游戏本地缓存中取出“藏品图鉴”数据并生成 CSV 的方法。后续游戏更新时，优先按此流程重新导出；**不需要依赖启动抓包**。

## 一、让微信写入最新资源

1. 在微信中打开该小游戏并进入“藏品图鉴”，等待图鉴内容正常显示。
2. 退出图鉴后再开始导出。这样 Unity 的资源包通常已经落到本地缓存。

本次游戏的 AppID 为 `wxbe6846b9b2bcd23f`。Windows 缓存目录为：

```text
%APPDATA%\Tencent\xwechat\radium\users\<微信用户目录>\applet\local\wxbe6846b9b2bcd23f\usr\__GAME_FILE_CACHE\Assets\ab
```

其中 `<微信用户目录>` 是一串账号目录名。本次实际使用的资源包为：

```text
assets_resources_config_resbin_3662609916.ab
```

更新后文件名的数字可能改变。应在 `Assets\ab` 中查找所有 `assets_resources_config_resbin_*.ab`，并优先检查最近更新时间的文件。

## 二、确认资源包内有图鉴配置

资源包是 Unity AssetBundle。用 Python 的 `UnityPy` 读取，查找名称为 `AuctionCollectionBaseConfig` 的 `TextAsset`。找到该资产即说明是目标数据。

一次性安装解析依赖：

```cmd
python -m pip install --target .unitypy2 UnityPy
```

本目录中的 `inspect_unity_bundle.py` 可用于确认资产名。示例：

```cmd
set PYTHONPATH=.unitypy2
python inspect_unity_bundle.py <资源包完整路径>
```

输出中应包含：

```text
TextAsset  ...  AuctionCollectionBaseConfig
```

## 三、解析原始记录

运行项目中的 `tools/collection_catalog/extract_auction_records.py`：

```cmd
.venv\Scripts\python tools\collection_catalog\extract_auction_records.py <资源包完整路径> --raw-output data\auction_collections_raw.csv
```

资源包路径通过第一个命令行参数传入。游戏更新后，无需改脚本，只需替换命令中的 `assets_resources_config_resbin_*.ab` 路径。

脚本会生成 `auction_collections_raw.csv`。本次结果为 `parsed=830`，其中包含藏品和功能道具两种记录。

### 二进制结构要点

- `AuctionCollectionBaseConfig` 的记录总数是大端无符号整数，位于偏移 `12`。
- 首条记录起始偏移为 `20`。
- 每条记录开头依次是：`ID`、名称、描述、9 个大端 `uint32` 字段、普通图标 ID、详情图标 ID。
- 名称、描述、图标 ID 采用“4 字节长度 + UTF-8 字符串 + NUL 终止符”。
- 记录末尾存在长度不固定的扩展字段。因此脚本用下一条合法 `ID + 名称 + 描述` 的特征扫描来定位下一条记录；不要把记录长度写死。

## 四、字段映射与筛选规则

只保留 `field_1 == 1` 的行；这是实际的“藏品”。`field_1 == 2` 是扫描仪、灯、锤等功能道具，应排除。

| 原始字段 | CSV 字段 | 映射规则 |
| --- | --- | --- |
| `name` | 名称 | 原始名称 |
| `field_4`、`field_5`、`field_6` | 轮廓 | 输出为 `宽×高（总格数）`，如 `2×2（4格）` |
| `value` | 价值 | 原始基础价值 |
| `field_3` | 品质 | `1~6` 分别为白品、绿品、蓝品、紫品、橙品、红品 |
| `field_2` | 品类 | `1~6` 分别为古董、珠宝、奢品、字画、化石、茗酿 |
| `description` | 描述 | 原始说明 |
| `icon` | 图标资源 ID | Unity 图标资源名，便于后续提取图片 |

“轮廓”对应游戏中仓库格位所显示的宽、高和占格数，例如 `3×2（6格）`。

## 五、生成最终 CSV

原始 CSV 成功生成后，运行：

```cmd
node tools\collection_catalog\build_collection_csv.mjs data\auction_collections_raw.csv data\藏品图鉴汇总.csv
```

输出文件为：

```text
data\藏品图鉴汇总.csv
```

导出脚本会：

1. 按 `field_1 == 1` 筛选；
2. 套用上述品质和品类映射；
3. 按藏品 ID 排序；
4. 用 UTF-8 with BOM 写入 CSV，Excel 直接打开不会出现中文乱码。

## 六、更新后核对清单

- `AuctionCollectionBaseConfig` 能被找到；
- 解析出的记录数没有异常减少；
- 最终 CSV 行数 = 藏品数 + 1（表头）；
- 品类只应出现：古董、珠宝、奢品、字画、化石、茗酿；
- 品质只应出现：白品、绿品、蓝品、紫品、橙品、红品；
- 若出现新的品类、品质编号或脚本无法扫描到下一条记录，保留新的资源包和报错位置，再更新解析规则。
